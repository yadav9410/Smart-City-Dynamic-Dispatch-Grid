# Phase 16.10 — Deployment and Launch Preparation

This guide prepares the app for a limited, public **demonstration** using Streamlit Community Cloud. It does not perform the deployment for you. The app is not an emergency service and must not be promoted as one.

## Safety boundary before deployment

- Keep the app clearly labeled as a prototype; it does not contact emergency services or dispatch responders.
- For immediate emergencies in India, users should call **112** directly.
- Do not encourage users to submit real emergency, health, identifying, or otherwise sensitive reports during a public demo.
- Reports saved in PostgreSQL remain until an operator/admin handles them. Automatic retention/deletion is not implemented in this prototype.
- The current operator console uses one shared password hash and prototype-level session controls. Do not use it to protect a production emergency-response service.
- Session throttling is not IP-wide or account-wide. Hosting-layer rate limits/WAF controls are still required before broad public use.

## A. Prepare the repository

1. Download and extract the latest `smart_city_dispatch_grid` project ZIP.
2. From the project root, install and test with Python 3.12 (matching the selected Community Cloud runtime):

   ```bash
   python -m venv .venv
   # Windows PowerShell: .venv\Scripts\Activate.ps1
   # macOS/Linux: source .venv/bin/activate
   python -m pip install --upgrade pip
   python -m pip install -r requirements.txt
   python -m compileall -q app.py smartcity tests scripts
   python -m pytest -q
   python scripts/deployment_preflight.py --static-only
   ```

3. Configure local secrets in `.streamlit/secrets.toml` (copied from `.streamlit/secrets.toml.example`) or environment variables. Never commit `.streamlit/secrets.toml`, `.env`, or any real secrets.
4. Confirm the following secrets are ready:
   - `DATABASE_URL`: PostgreSQL URL with TLS/SSL enabled as required by your provider.
   - `OPERATOR_PASSWORD_HASH`: hash generated using `python -m smartcity.operator_auth`; never use a plaintext password here.
   - `GROQ_API_KEY`: needed for voice transcription and the fallback AI assessment. If omitted, those features will not be available.
5. From the intended database environment, run the idempotent schema initializer once after confirming `DATABASE_URL` points to the correct database:

   ```bash
   python -c "from smartcity.storage.postgres import initialize_database; initialize_database(); print('Schema initialization completed')"
   ```

   This creates the app tables/indexes. It does not migrate your old Colab SQLite database. Do not run it with a connection URL you have not checked.
6. Run a safe configuration check. The checker never prints credential values:

   ```bash
   python scripts/deployment_preflight.py
   python scripts/deployment_preflight.py --check-db
   ```

   The second command only performs read-only table-existence queries; it does not initialize or modify the schema. Do not share terminal output that contains information from your own infrastructure beyond the generic status lines.

## B. Push to GitHub

1. Create a GitHub repository for this project. For the first test, keep repository access limited while you inspect the files.
2. Upload/push the extracted project so `app.py`, `requirements.txt`, `.streamlit/config.toml`, `smartcity/`, `tests/`, and `.github/workflows/ci.yml` are at the repository root as shown in the ZIP.
3. Before the first push, inspect staged files and confirm `.streamlit/secrets.toml`, `.env`, database exports, real incident data, and API keys are not included.
4. GitHub Actions runs the unit tests on Python 3.12 for pushes and pull requests. Wait for the workflow to pass before deploying.

## C. Deploy on Streamlit Community Cloud

1. Open [Streamlit Community Cloud](https://share.streamlit.io/) and sign in with GitHub.
2. Select **Create app** and choose the repository, deployment branch (usually `main`), and entrypoint file `app.py`.
3. Open **Advanced settings** and select Python **3.12**.
4. Add secrets in the deployment settings' **Secrets** field. Enter TOML values directly into the secrets editor; do not create/commit a real `secrets.toml` in Git. An example shape is below—replace every placeholder with your own value before saving:

   ```toml
   DATABASE_URL = "postgresql://YOUR_USER:YOUR_PASSWORD@YOUR_HOST/YOUR_DATABASE?sslmode=require"
   GROQ_API_KEY = "YOUR_GROQ_API_KEY"
   OPERATOR_PASSWORD_HASH = "pbkdf2_sha256$..."
   MAX_REPORT_CHARS = 3000
   AGENT_MODEL = "openai/gpt-oss-120b"
   ```

   Keep `OPERATOR_PASSWORD_HASH` to the complete hash generated by the helper. Do not paste the placeholder value above literally. Confirm with your database provider whether its connection URL should use a pooled endpoint for this workload.
5. Deploy and inspect Cloud logs if startup fails. The first build installs the packages from `requirements.txt`.
6. Open the app only for a limited test audience until all steps in the launch checklist below are verified. Review the app's sharing settings before publishing its URL.

Official instructions: [Deploy an app](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy), [Secrets management](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management), [App settings](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/app-settings), and [Dependency configuration](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies).

## D. Post-deployment smoke test

Use only fictional data. Verify each item manually in the deployed browser:

- The landing page visibly states that this is a prototype and that real emergency services are not connected.
- The emergency instruction clearly says to call 112 for immediate emergencies in India.
- Text report submission stores a test report only after the explicit consent checks and shows a reference receipt.
- Location is not stored when location consent is unchecked; when consented, the selected location is shown as user-provided data, not a responder location.
- Browser GPS is tested only over HTTPS with permission granted; manual pin/coordinate fallback works if permission is denied.
- Audio is not sent to Groq until the explicit transcription consent and button click; transcript is editable before submission.
- Mock resource markers/routes carry simulation labels; no live resource availability, road ETA, or real dispatch is claimed.
- AI assessment is explicit, and no public action invokes automatic assignment/reservation.
- Operator console rejects an invalid password, works with the configured hash, times out after inactivity, and does not reveal reports while logged out.
- Rate limits work in a single session. Document that session limits are not a substitute for WAF/IP-wide controls.
- Database failure produces a generic message, not a connection string or raw exception.
- No secret values or report content appear in browser errors, screenshots, issue reports, or public source control.

If any privacy, authentication, or consent check fails, unpublish/restrict access and fix it before inviting more testers.

## E. Rollback and operations

- To roll back app code, revert the corresponding Git commit and let Community Cloud redeploy.
- If credentials are exposed, revoke/rotate them immediately; deleting a Git commit alone may not remove copies from history or logs.
- Review database backups, least-privilege access, and a retention/deletion policy before collecting real personal data. The app does not yet automatically delete reports.
- Monitor app logs without exporting report text, raw audio, location, or secrets into support tickets.
- Community Cloud may sleep/restart apps. PostgreSQL is the persistent store; do not rely on Streamlit session state as durable storage.

## Completion criterion

Phase 16.10 is complete only after the repository workflow passes, the app deploys successfully, the database schema is verified, secrets are configured outside Git, and the post-deployment smoke test is completed. Creating this deployment package alone does not mean the app is live.


## Configure secrets on Streamlit Community Cloud

After deployment, open the app's **Manage app → Settings → Secrets** screen and paste a TOML block using your newly rotated credentials. Do not commit the real values into GitHub or any file in this repository. Example shape (replace placeholders with real values only in the Cloud Secrets editor):

```toml
GROQ_API_KEY = "PASTE_NEW_ROTATED_GROQ_KEY_HERE"
DATABASE_URL = "PASTE_NEW_ROTATED_NEON_CONNECTION_STRING_HERE"
OPERATOR_PASSWORD_HASH = "PASTE_GENERATED_PBKDF2_HASH_HERE"
AGENT_MODEL = "openai/gpt-oss-120b"
```

Click **Save** and wait for Streamlit to restart. The app reads these values through `st.secrets`; the voice and database setup notices disappear automatically once the corresponding secret is present. The report form still requires a successful database schema initialization. This project intentionally does not embed or echo any actual credentials.

**Credential rotation:** any key or database password pasted into chat, a public issue, or a Git commit should be treated as exposed. Revoke the Groq key and reset the Neon database role password, copy the fresh connection string from Neon, and update the Cloud Secrets values.
